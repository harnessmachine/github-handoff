# GitHub Handoff

**Простой русскоязычный skill, который сохраняет контекст AI-сессии в GitHub Issue.**

Он нужен, чтобы закрыть старый чат, открыть новый и продолжить задачу без ручного пересказа всей переписки.

В конце сессии агент оставляет в Issue короткий handoff:

- что сделано;
- какие решения приняты;
- что проверено;
- где лежат результаты;
- с какого шага продолжать.

В новом чате вы отправляете агенту ссылку на Issue. Он читает задачу и последний handoff, проверяет актуальное состояние проекта и продолжает работу.

## Главная идея

```text
описание Issue = что нужно сделать
handoff-комментарий = где остановились
новый чат = читает Issue и продолжает
```

GitHub Issue здесь не является магической памятью модели. Это внешний источник контекста, доступный человеку и разным AI-агентам.

## Откуда появилась идея

Skill вдохновлён [`handoff` Matt Pocock](https://github.com/mattpocock/skills/tree/main/skills/productivity/handoff).

Оригинальный skill превращает текущий разговор в компактный переносимый документ. Он сохраняет только живой контекст, ссылается на уже существующие артефакты и исключает чувствительные данные.

`github-handoff` использует те же принципы, но сохраняет состояние сессии в GitHub Issue. Так handoff получает постоянную ссылку, остаётся доступным после закрытия чата и может быть прочитан другим агентом.

## Что умеет skill

- сохранить состояние текущей сессии в комментарии к Issue;
- создать простую Issue задачи по явной просьбе;
- восстановить контекст из описания и последнего handoff;
- сверить сохранённый контекст с живым состоянием проекта;
- подготовить Markdown для ручной вставки, если у агента нет доступа на запись.

Skill намеренно не управляет GitHub Projects, labels, milestones и полным бэклогом.

## Быстрый старт

Для Codex:

```bash
git clone https://github.com/harnessmachine/github-handoff.git ~/.codex/skills/github-handoff
```

Для Claude Code:

```bash
git clone https://github.com/harnessmachine/github-handoff.git ~/.claude/skills/github-handoff
```

После установки перезапустите сессию агента, если он не обнаружил skill автоматически.

Если ваш агент использует другую папку для skills, склонируйте репозиторий туда. Главное, чтобы `SKILL.md` лежал в корне папки `github-handoff`.

## Что понадобится

- GitHub-репозиторий с включёнными Issues;
- AI-агент с поддержкой skills;
- доступ агента к GitHub через connector, API или авторизованный `gh` CLI.

## Перед первым использованием

1. Создайте репозиторий на GitHub или откройте существующий.
2. Убедитесь, что в репозитории включены Issues.
3. Создайте одну Issue для реальной задачи.
4. Если данные нельзя публиковать, используйте приватный репозиторий.
5. Дайте агенту доступ к GitHub через доступный connector, API или авторизованный `gh` CLI.

## Сохранить текущую сессию

Отправьте агенту:

```text
Используй $github-handoff и сохрани текущую сессию в эту Issue:

https://github.com/OWNER/REPO/issues/123

Следующая сессия должна продолжить реализацию.
```

Агент добавит компактный комментарий и вернёт ссылку вместе с промптом для нового чата.

## Продолжить в новом чате

Отправьте новому агенту:

```text
Используй $github-handoff и продолжи работу по этой Issue:

https://github.com/OWNER/REPO/issues/123

Сначала прочитай описание и последний handoff.
Сверь их с текущим состоянием проекта.
Коротко скажи, что восстановил, и продолжи с ближайшего шага.
```

## Пример handoff-комментария

```markdown
<!-- github-handoff session: 24a76590-25ad-4a51-b7c8-6c892488fc30 -->

## handoff · 2026-09-16

### цель следующей сессии

Завершить форму регистрации и проверить отправку данных.

### результат текущей сессии

- Собрана форма из трёх полей.
- Добавлена клиентская валидация email.

### актуальное состояние

- Интерфейс готов.
- Отправка на сервер ещё не подключена.

### решения и ограничения

- Использовать существующий API route `/api/signup`.
- Не добавлять новую библиотеку форм.

### проверка

- Локальная сборка проходит.
- Серверный запрос ещё не проверялся.

### ближайший шаг

Подключить submit формы к `/api/signup` и проверить успешный и ошибочный ответы.

### файлы и ссылки

- `src/components/SignupForm.tsx`
- `src/app/api/signup/route.ts`

### промпт для продолжения

Продолжи работу по этой GitHub Issue: https://github.com/OWNER/REPO/issues/123
Сначала прочитай описание и последний handoff, сверь их с текущим состоянием проекта и продолжи с ближайшего шага.
```

## Три уровня развития

```text
уровень 1: одна задача, одна Issue, handoff между чатами
уровень 2: несколько связанных Issues и разделение задач
уровень 3: GitHub Projects, статусы и управление системой
```

Этот skill обучает только первому уровню.

## Безопасность

Не сохраняйте в GitHub Issue:

- токены, пароли, cookies и содержимое `.env`;
- персональные и конфиденциальные данные;
- полные приватные разговоры;
- большие логи и дампы терминала.

Перед использованием проверьте, публичный репозиторий или приватный.
